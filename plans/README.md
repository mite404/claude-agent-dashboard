## Dependency notes

- The three plans are independent and can be executed in any order or in
  parallel by separate agents — they touch disjoint files, **except**:
  Plans 002 and 003 both modify `scripts/post-tool-all.ts`. If both are run,
  apply **002 first**, then 003, to avoid overlapping edits. 003's change to that
  file (wrapping the parse) is orthogonal to 002's (the health-check URL), so
  after 002 lands, 003 applies cleanly.
- Recommended order is simply numeric: 001 (highest security impact) → 002 → 003.

## Scope note

These four findings were packaged into three plan files because findings #1
(SEC-02, spawn CSRF) and #2 (SEC-01, all-interface bind) both harden the same two
server files and must ship together — splitting them would mean two plans editing
`scripts/spawn-terminal.ts` at once. Plan 001 covers both.
